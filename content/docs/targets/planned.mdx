The Go-era `gset.conf` carried keyword stubs for a long list of languages. That scaffolding is **gone** — building a target is now a real backend implementing the `Backend` trait, not a config row.

## The sequence in the rewrite plan

| Milestone | Adds |
|-----------|------|
| M2 | JavaScript/TypeScript frontend; Python, JavaScript, Java, Ruby backends |
| M3 | Go, Java, Ruby, then C/C++ and Rust frontends |
| M5 | dependency resolution for pip, npm, Cargo, Maven, Go modules |

Each new language is a **grammar dependency plus a lowering pass**, not a new compiler.

## What a new backend requires

1. Implement `Backend` — `id()`, `capability()`, `emit_module()`.
2. Emit through the shared `CodeWriter` (which owns indentation, so generated files never fail their checker due to formatting).
3. Clear the target-syntax gate: generated output must pass the target's own checker.
4. Golden files per frontend × backend pair.

## Suggested priority

| Target | Why |
|--------|-----|
| TypeScript | closest to the JS lowering path; pairs with the JS backend |
| C | small runtime, dominant in systems contexts |
| Rust | memory-safe C alternative with a single-binary toolchain |
| C# / Kotlin | typed OOP targets with existing `class` vision |
