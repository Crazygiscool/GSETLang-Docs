title: Configuration
description: gset.conf was removed in the Rust rewrite; gset.toml is planned but not implemented.
---

The Go-era `gset.conf` — keyword aliases, compiler overrides, and per-target print mappings — was **removed** with the Rust rewrite.

## Today

There is **no configuration file**. The CLI has no config-loading step before argument parsing, which is deliberate: a per-invocation config read (which the Go binary did even for `gset version`) is a startup-cost tax on exactly what the rewrite optimises for.

## Planned: `gset.toml`

The rewrite plan reserves a `gset.toml` carrying only what has real use:

- **default target** (`go`, unless `-t` is passed)
- **interpreter paths** for the runtimes `gset run` shells out to
- **project root** and **dependency search roots** (the `gset-deps` milestone)

None of this is implemented yet. Until it lands, `gset` behaves identically regardless of the directory you invoke it from.
