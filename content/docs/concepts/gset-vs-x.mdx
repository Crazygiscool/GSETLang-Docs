## GSET vs. Babel / TypeScript

| | Babel / TS | GSET |
|---|---|---|
| Input & output | JS → JS (transform / typecheck) | **any language → any language** (Python → Go today) |
| Typed core | TypeScript has a full type system | shared typed IR with `Unknown` propagation |
| Runtime | none added | shells to the target runtime |
| Purpose | transpile *within* one ecosystem | port *across* ecosystems |

GSET's output is genuine source in the target language — but every target is gated on that language's own syntax checker, so "valid output" is a CI assertion, not a claim.

## GSET vs. language-porting transpilers (2to3, 6to5, Cyclone)

Those tools convert one language to a close relative (Python 2→3, ES5→ES6). GSET converts real input languages to unrelated output languages through a shared IR — closer in spirit to a compiler frontend/backend split, but staying at the source level and never lowering to machine code.

## GSET vs. polyglot "run anywhere" layers (GraalVM, WASM)

| | Graal / WASM | GSET |
|---|---|---|
| Model | one runtime interprets many languages | parse many languages, emit to many runtimes |
| Typing | native per language | shared typed IR; conservative inference |
| Achievement | many languages, one runtime | many languages, many runtimes, source you keep |

GSET trades universal coverage for **real per-target output you can read, debug, and keep** — no VM layer.

## GSET vs. the original "any-language config" promise

The earliest vision was config-driven: point GSET at any language via `gset.conf` and it would speak it. The rewrite replaced that with **a real compiler pipeline**:

| Promise (README-era) | Reality (3.3.0) |
|----------------------|------------------|
| *any language, via config* | tree-sitter frontends + a typed IR; config file removed |
| *custom keywords in config* | gone — builtins are first-class in each backend |
| *five emitters that could emit broken syntax* | capability matrix + syntax-check gate; only Go ships today |

## When GSET fits

- Moving a Python codebase's logic to Go, with valid-syntax output.
- Learning how the same program looks in different target languages.
- The M2 milestone: a corpus of programs that compile and run on five runtimes.

## When it doesn't

- Big type-inference-sensitive codebases (inference is conservative; `Unknown` propagates).
- Semantic *preservation* across all language pairs (out of scope).
- Anything needing modules, classes-with-behavior, or OS-specific features before M4/M5.
